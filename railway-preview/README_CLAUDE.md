# はぐのまち鉄道：Claude引き継ぎ

## まずやること
このフォルダは Sites に依存しない独立した試作です。既存アプリへ統合する前に、このまま別ページで確認してください。既存ファイルや保存データは上書きしないでください。

1. このフォルダの全ファイルを読む。
2. `preview.html` は画像とコードを内包した単体確認用ファイル。PCのブラウザで直接開ける。編集には分離された `index.html` / CSS / JS を使う。`index.html` をPCで直接開くか、このフォルダで `python3 -m http.server 8000` を実行する。ビルド・npm・APIキー不要。iPhoneのファイルアプリ内プレビューはJavaScriptが動かない場合があるため、実機テストにはHTTPで配信したページをSafariで開く。
3. GitHub Pages の現在の公開ルートに `railway-preview/` フォルダとして追加する案を提示する。公開操作は所有者の指示に従う。公開後のパスは `railway-preview/index.html`。既存の `mitooshi_calendar.html` は変更しない。
4. 実機確認後に、既存のタスク／コイン／工房との接続箇所を提案する。試作の保存データをそのまま本番へ移行しない。

## デザインの意図
ユーザーが好むのは、立体的な街並み・緑の環状線・本物の車内案内に近い行先表示。平面的なパステルのイラストへ置き換えない。立体感は静止画像で、文字・駅・時計はHTML/SVGで描く。生成画像にタスク名や時刻を焼き込まない。

画面中央の時計は「現在タスクの目標時刻」。その下の小さい「いま」は現在時刻。車内モニター下部には終点・おふとんの目標時刻。時刻はすべて親が設定できる。同じ時計に現在と目標の針を重ねていない。

駅順は固定の一本道。早寝の日4駅／いつもの日10駅／習い事の日8駅／外食の日6駅。10駅時は地図の文字が混雑しないよう、現在駅と終点以外は番号表示。ヘッダーの停車駅案内で全駅と時刻を確認する。終点を最後に保ち、その他の駅順を親が変更できる。

「できた」を押すと完了数はすぐ反映、電車だけが700msで次駅へ移動する。その間は連打を防止。全駅完了後は静かな終了表示で止まる。画面内で周回し続けない。減点、遅刻警告、カウントダウン、追加の収集報酬は入れていない。

## 実装上の範囲
- バックエンド、外部ライブラリ、外部フォント、AI API呼び出し、アクセス解析なし。
- サーバー課金・認証・決済・同期・PWAキャッシュは未実装。
- ブラウザの `localStorage` の専用キー `hagu_railway_portable_v1` のみ使用。既存アプリのキーは読み書きしない。保存不能でも操作は可能。
- 日付は端末ローカル。日付変更時に完了数だけリセット。目標時刻／選択コースは保持。
- 現段階で保存されるのは選択中の1コースの設定。別コースへ切り替えると既定時刻から作り直す。コースごとの個別カスタム設定を複数永続保存する機能は未実装。
- 時刻は同一日内・昇順（同時刻は可）。日をまたぐスケジュールは検証で拒否。
- おうちのひとボタンは通常タップ。長押しゲート／保護者認証は未実装。
- CSSの動きを減らす設定に対応。画面を離れたら移動演出を終了。時計は30秒ごとに更新。
- 画像は本物の3Dではない。駅の数・順番・文字はコードで変えられる。電車は平面素材が線路に沿って回転する。
- 絵文字はタスク識別の補助。端末により見た目が変わる。今後タスク素材を差し替える場合も中心の街並み・案内板の方向性を維持。

## 次に確認する優先順位
1. ユーザーのiPhone Safariで表示・タップ・復帰・保存を確認する。
2. 3〜6歳の利用で「今やること」「次」「時計」の意味が伝わるか確認する。
3. 親が選んだ順番を既存アプリのタスクIDに紐づけるアダプターを設計する。

性能はコードと容量だけで保証しない。初回読み込み・再訪・電車の移動・発熱・古い端末で確認する。この試作から課金可能性や習慣化の効果を断定しない。
